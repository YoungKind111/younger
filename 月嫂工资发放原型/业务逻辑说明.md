# 月嫂工资发放系统 — 业务逻辑说明

## 一、页面结构

### 1.1 表格列（共 14 列）

| 序号 | 列名 | 说明 |
|------|------|------|
| 1 | 复选框 | 全选/单选，用于批量操作 |
| 2 | 月嫂姓名 | 月嫂姓名 |
| 3 | 客户 | 客户姓名 |
| 4 | 订单实收金额 | 绿色可点击，点击弹出收款/退款记录弹窗 |
| 5 | 工资期数 | 如：26天、42天 |
| 6 | 结算等级 | 月嫂等级 |
| 7 | 应发工资 | 红色可点击，点击弹出工资计算明细弹窗 |
| 8 | 专属客服 | 负责该订单的客服人员 |
| 9 | 月嫂老师 | 月嫂的运营老师 |
| 10 | 审核状态 | 8 种状态，见下方 |
| 11 | 发放状态 | 4 种状态，见下方 |
| 12 | 实发工资 | 实际已发放的金额 |
| 13 | 易宝资金缺口 | 应发工资与易宝可用资金的差额 |
| 14 | 操作 | 动态按钮（查看/编辑/删除/审核日志/缺口处理） |

---

## 二、审核状态体系（共 8 种）

审核状态控制工资单的审批流程，从草稿到最终审核通过。

| 审核状态 | 标签颜色 | 说明 |
|----------|----------|------|
| 草稿 | 灰色 | 初始状态，可编辑 |
| 待专属客服审核 | 蓝色 | 提交后流转至专属客服 |
| 待薪酬审核 | 紫色 | 专属客服审核通过后流转至薪酬部门 |
| 待月嫂老师（运营）审核 | 橙色 | 薪酬审核通过后流转至运营 |
| 待月嫂确认 | 青色 | 运营审核通过后流转至月嫂本人确认 |
| 待薪酬复核 | 粉色 | 月嫂确认后流转回薪酬复核 |
| 待财务审核 | 红色 | 运营核对后流转至财务 |
| 审核通过 | 绿色 | 财务审核通过，进入发放流程 |

### 2.1 状态迁移路径

```
草稿 → 待专属客服审核 → 待薪酬审核 → 待月嫂老师（运营）审核
  → 待月嫂确认 → 待薪酬复核 → 待财务审核 → 审核通过
```

> 每个中间状态均可审核不通过退回至上一状态（本原型未体现退回逻辑）。

---

## 三、发放状态体系（共 4 种）

发放状态独立于审核状态，专门控制工资的实际发放流程。

| 发放状态 | 标签颜色 | 说明 |
|----------|----------|------|
| 未发放 | 灰色 | 审核未通过或未进入发放流程 |
| 待出纳发放 | 金色 | 审核已通过，等待出纳执行出款 |
| 发放部分 | 橙色 | 已发放部分工资，仍有资金缺口 |
| 发放全部 | 绿色 | 工资已全部发放完毕 |

### 3.1 审核状态与发放状态的对应关系

- 当发放状态为 **待出纳发放 / 发放部分 / 发放全部** 时，审核状态必须为 **审核通过**
- 发放状态为 **未发放** 时，审核状态可以是除"审核通过"外的任意状态

---

## 四、应发工资计算逻辑

### 4.1 计算公式

```
应发工资 = 基础工资 + 奖励 − 扣罚 − 支出
```

### 4.2 各分项说明

| 分项 | 符号 | 说明 |
|------|------|------|
| 基础工资 | + | 月嫂的基本工资，根据结算等级和工资期数确定 |
| 奖励 | + | 各类奖励（好评奖、全勤奖、推荐奖等） |
| 扣罚 | − | 各类扣罚（差评扣款、迟到早退、物品损坏等） |
| 支出 | − | 其他支出（住宿费、交通费、培训费等） |

### 4.3 弹窗展示格式

顶部汇总区显示完整公式：
```
¥9,800.00 = ¥9,800.00 + ¥0.00 − ¥0.00 − ¥0.00
```

下方分模块展示：基础信息、奖励明细、扣发明细、支出明细、备注。

---

## 五、易宝资金缺口计算逻辑

### 5.1 计算公式

```
易宝资金缺口 = 应发工资 − (易宝收款总额 − 易宝退款总额)
```

### 5.2 统计规则

- **易宝收款**：仅统计 **支付方式 = 易宝** 且 **审核状态 = 审核通过** 的收款记录
- **易宝退款**：仅统计 **关联易宝支付单号** 且 **审核状态 = 审核通过** 的退款记录

### 5.3 缺口显示规则

| 条件 | 显示 |
|------|------|
| 缺口 ≤ 0（资金充足） | 绿色短横线 `-` |
| 缺口 > 0（资金不足） | 红色数字 `¥XX,XXX.XX` |

### 5.4 业务背景

- **老系统**（盛付通/银行转账）的收款 **不可用于新系统自动发薪**
- **新系统**仅 **易宝** 支持自动出款
- 跨系统订单会产生资金缺口，需出纳手动处理

## 六、按钮交互规则

### 6.1 顶部批量操作按钮

| 按钮 | 启用条件 | 禁用条件 |
|------|----------|----------|
| **审核通过** | 选中任意【草稿 ~ 待财务审核】状态的数据 | 选中【审核通过】状态，或无选中 |
| **支付工资** | 选中的数据发放状态为【待出纳发放】 | 选中数据不满足条件，或无选中 |

### 6.2 单行操作按钮（动态显示）

| 按钮 | 显示条件 |
|------|----------|
| 查看 | 所有状态均显示 |
| 编辑 | 审核状态 **非**【待财务审核 / 审核通过】时显示 |
| 删除 | 审核状态为【草稿】时显示 |
| 审核日志 | 审核状态 **非**【草稿】时显示 |
| 缺口处理 | 审核状态为【审核通过】且存在资金缺口时显示，缺口清零后自动隐藏 |

---

## 七、复选框控制规则

- 【审核通过】状态的数据，复选框**置灰且不可点击**
- 悬浮提示：`"审核通过数据不可选中"`
- 点击全选时，自动跳过【审核通过】的数据

---

## 八、缺口处理流程

### 8.1 触发条件

- 审核状态 = **审核通过**
- 易宝资金缺口 > 0
- 操作栏显示【缺口处理】按钮

### 8.2 处理弹窗

出纳手动分配缺口资金到以下渠道：

| 渠道 | 字段 | 说明 |
|------|------|------|
| 盛付通 | `gapAmt-sft` | 盛付通转账金额 |
| 银行转账 | `gapAmt-bank` | 银行转账金额 |
| 其他 | `gapAmt-other` | 其他方式金额 |

每项需填写**打款编号**。

### 8.3 保存规则

- 分配总额 ≥ 缺口金额时，方可保存
- 保存后更新列表：
  - 实发工资 = 原实发 + 分配总额
  - 易宝资金缺口 = 绿色短横线 `-`
  - 发放状态 = **发放全部**
  - 【缺口处理】按钮自动隐藏

---

## 九、弹窗说明

### 9.1 订单实收金额弹窗（`paymentModal`）

点击绿色订单实收金额触发，展示：
- 订单号
- **收款记录表**：支付单号、系统来源、支付方式、金额、时间、审核状态
- **退款记录表**：关联支付单号、系统来源、支付方式、金额、时间、审核状态

### 9.2 应发工资弹窗（`salaryModal`）

点击红色应发工资金额触发，展示：
- 顶部计算汇总：`应发 = 基础 + 奖励 − 扣罚 − 支出`
- **基础信息**：基础工资金额
- **奖励明细**：各项奖励列表及汇总
- **扣发明细**：各项扣罚列表及汇总
- **支出明细**：各项支出列表及汇总
- **备注**：工资单备注信息

### 9.3 缺口处理弹窗（`gapModal`）

点击【缺口处理】按钮触发，展示：
- 当前缺口金额
- 分配渠道输入框（盛付通/银行转账/其他）
- 各渠道打款编号输入框
- 保存按钮（需满足分配总额 ≥ 缺口金额）

## 十二、核心规则速查

1. **审核通过**的数据不可编辑、不可删除、不可选中
2. **待出纳发放**的数据可以执行【支付工资】批量操作
3. 只有【审核通过 + 存在资金缺口】的数据才显示【缺口处理】按钮
4. 易宝资金缺口仅统计**支付方式=易宝**且**审核通过**的收款和退款
5. 缺口处理保存后，发放状态自动变为**发放全部**
6. 应发工资 = 基础工资 + 奖励 − 扣罚 − 支出
