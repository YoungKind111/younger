# 退款审核 — 业务逻辑与流程规则

---

## 一、审批流程

### 1.1 签合同前（未签署合同）
**3 步审批链**：
```
发起人（郑安胜）→ 部门负责人（张三）→ 销售负责人（植亚来）
```

### 1.2 签合同后（已签署合同）
**7 步审批链**：
```
发起人（郑安胜）→ 部门负责人（张三）→ 销售负责人（植亚来）
→ 质量监督官（梁艳红）→ 会计（何才连）→ 财务负责人（尹俊）→ 总经理（卓大龙）
```

---

## 二、审批状态流转

| 状态 | 说明 |
|---|---|
| 待部门负责人审核 | 发起人提交后，等待部门负责人审批 |
| 待销售负责人审批 | 部门负责人通过后，等待销售负责人审批 |
| 待质量监督官审批 | 销售负责人通过后，等待质量监督官审批（仅签合同后） |
| 待会计审核审批 | 质量监督官通过后，等待会计审批（仅签合同后） |
| 待财务负责人审核 | 会计通过后，等待财务负责人审批（仅签合同后） |
| 待总经理审核 | 财务负责人通过后，等待总经理审批（仅签合同后） |
| 审核通过 | 所有节点审批通过，进入发放流程 |
| 审核不通过 | 任意节点驳回，流程终止 |

---

## 三、发放状态规则

| 状态 | 触发条件 |
|---|---|
| **未打款** | 默认状态。审核未通过或审核刚通过时 |
| 出纳待打款 | 审核已通过，等待出纳执行打款 |
| 退款成功 | 出纳已打款，退款完成 |

### 3.1 发放状态与来源系统的绑定规则

| 来源 | 审核状态 | 发放状态 |
|---|---|---|
| 新系统 | 审核通过 | **退款成功** |
| 旧系统 | 审核通过 | **出纳待打款**（旧系统最高只能到待打款，无法自动标记为退款成功） |
| 新系统 / 旧系统 | 审核不通过 / 待审核 | **未打款** |

### 3.2 发放状态流转

```
未打款 → 审核通过 → 出纳待打款 → 【确认打款】→ 退款成功
         ↓
      审核不通过（终止）
```

---

## 四、操作按钮显示规则

### 4.1 退款单按钮
- **仅当「审核状态 = 审核通过」时显示**
- 审核不通过、待审核等状态均不显示

### 4.2 审核按钮
- **仅当「审核状态 = 待审核」时显示**
- 审核通过、审核不通过均不显示

### 4.3 确认打款按钮
- **仅当「发放状态 = 出纳待打款」时显示**
- 点击后打开出纳打款弹窗，填写打款渠道和打款编号后保存
- 保存后发放状态由「出纳待打款」实时更新为「退款成功」
- 打款信息同步回填到该行的审批记录弹窗中

### 4.4 按钮顺序
审核记录 → 订单 → （审核 / 退款单 / 确认打款）

---

## 五、审批记录弹窗规则

### 5.1 显示内容
- 已完成的节点：显示审核日期、意见、通过状态
- 当前待审及后续节点：显示为「待审核」，标注对应审批人
- 审核不通过：仅显示到驳回节点，后续节点不再展示

### 5.2 底部信息
- 退款原因
- 退款描述
- 附件列表
- **打款渠道**（仅退款成功时展示，位于最底部）
- **打款编号**（仅退款成功时展示，位于最底部）

---

## 六、退款审核弹窗规则

- 仅点击「审核」按钮时打开
- 显示退款金额、退款原因、退款描述、附件
- 审核人需填写审核备注后选择「不通过」或「通过」

---

## 七、出纳打款弹窗规则

- 仅点击「确认打款」按钮时打开
- 显示打款金额
- 需填写：打款渠道、打款编号（均为必填）
- 点击「保存」后：
  - 列表中对应行的发放状态由「出纳待打款」更新为「退款成功」
  - 打款渠道和编号回填到该行的审批记录弹窗中

---

## 八、数据联动规则

列表中的「审核状态」与审批记录弹窗内容必须一一对应：

| 列表审核状态 | 弹窗应展示 |
|---|---|
| 审核通过 | 完整审批链全部通过 |
| 待质量监督官审批 | 前3步已通过，第4步及后续待审 |
| 待销售负责人审批 | 前2步已通过，第3步及后续待审 |
| 待部门负责人审核 | 仅提交完成，第2步及后续待审 |
| 待财务负责人审核 | 前5步已通过，第6步及后续待审 |
| 审核不通过 | 显示到驳回节点为止 |

---

## 九、收款类型

预售金、诚意金、定金、合同款

---

## 十、支付方式

盛付通码牌支付、盛付通铠尔(对公)、盛付通铠尔码牌、盛付通码付(农商)、银行转账、动态支付码、现金

### 10.1 支付方式与来源系统的绑定规则

- **只有新系统才支持「动态支付码」**
- **盛付通系列（码牌支付、铠尔对公、铠尔码牌、码付农商）仅对应旧系统**
- 旧系统不支持动态支付码，仅支持盛付通系列、银行转账、现金
- 新系统支持除盛付通系列外的所有支付方式（含动态支付码、银行转账、现金）
