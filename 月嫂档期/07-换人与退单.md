# 07 · 换人与退单：幽灵档期两个产地的专项封堵

> **环节定位**：幽灵档期（系统里有、现实里没有的档期段）主要有两个产地：**换人漏录**和**退款漏删**。本环节用「自动生成 + 流程硬卡点」把两个产地堵死——共同原则是**不靠人记得**。
> **SLA**：换人接续段在 B 打卡时即时生成；退款删段为流程必经节点。
> **总览**：[00-总览.md](00-总览.md)

---

## 一、这个环节档期会怎么不准

| #   | 失真场景                  | 后果                                            |
| --- | --------------------- | --------------------------------------------- |
| 1   | 换人后 B 的档期靠手工补录，漏录     | **人在上户、系统显示空闲——水位高估里最危险的一种**，销售会把一个正在服务的人再卖出去 |
| 2   | A 的档期不收缩，A、B 同时占同一段时间 | 一段时间内两个人都显示上户，数据自相矛盾                          |
| 3   | 退款完成但档期段没删            | 幽灵档期长期占水位，可售池被压低                              |
| 4   | 换人交接期（A 已走 B 未到）没人管   | 服务空窗无记录，客诉时无法还原                               |

## 二、要做的事

### A. 换人七触发（明确什么算换人）

1. A 未下户（中途更换）；
2. 客户预产期提前（原月嫂接不上）；
3. 客户预产期延后；
4. 服务前退单重匹配；
5. **A 离职**（人态离职，无法继续服务，2026-08-26 新增）；
6. **A 爽约/飞单**（已定档但临时不去上户，2026-08-26 新增）；
7. **A 停单**（客诉/违规暂停接单，无法继续服务，2026-08-26 新增）。

### A2. 离职/停单/爽约场景：档期段分治（2026-08-26）

人离职、停单或爽约时，她名下的档期段按状态分治——**先释放补救、后追责**，档期处置与定责解耦：

| 段状态 | 处置 | 后续 |
|---|---|---|
| 锁档段 | **自动释放删段**（三触发同规则），时间回可售池 | 订单回池重新匹配，销售/客服收通知 |
| 定档段 | **释放删段**（原因=离职/停单/爽约，落流水；停单解除时间不确定，订单不等） | 订单进换人流程：B 按「合同已签 → 运营直排直接定档」补位；定责（积分 -50 / 黑名单，Sheet 18 / Sheet 19【四】）走事后 |
| 上户中段 | 离职/爽约：收缩到实际下户日（只收缩不删段）；**停单：红线/重大违规 → 强制下户（段收缩），轻微情形运营组可判定留任至本单结束（判定留痕）** | 强制下户/换人时 B 接续段自动生成（见 B 节） |
| 历史已结束段 | 不动 | 履历留痕 |
| 请假叠加层 | 随离职/停单/爽约处置一并清理 | — |

处置延迟的兜底：「人已离职/停单但仍有未关闭档期段」进每日对账清单（见 [08-事后对账与抽检.md](08-事后对账与抽检.md)）。

### B. B 接续段系统自动生成

- 按**订单接续关系**自动生成 B 的上户中段：开始日 = B 实际上户打卡日，结束日按订单剩余天数推算；
- **关闭手工补录入口**——手工能补就永远有人漏补；
- B 的打卡走 [05-上户与下户.md](05-上户与下户.md) 同一套双校验（扫码 + 客户确认，定位暂缓），接续段随打卡即时生效。

### C. A 段自动收缩

- A 的档期段收缩到实际下户日（提前下户只收缩日期范围、状态不变，Sheet 20 口径）；
- 交接空窗（A 下户日 → B 上户日之间）在订单时间轴上显式标注，不生成任何人的档期段。

### C2. 顶班 vs 换人：边界（2026-08-26）

- **顶班**（A 还会回本单）：服务中月嫂请假/临时有事 → 顶班人生成**短期上户中段**（开始=顶班打卡日、结束=顶班下户日，系统按订单顶班关系生成，同样禁手工补录）；**A 的段不收缩不删除**（服务延续），A 的请假天数走请假叠加层；顶班段履历记「中途顶班」履约类型（Sheet 9）；
- **换人**（A 不再回来）：按 A2/B/C 机制，A 段收缩、B 段接续；
- 边界判定 = A 是否回本单；**顶班超 7 天自动提示评估是否转正式换人**（⚠️ 阈值待业务确认）；
- 顶班人打卡与客户确认走 [05-上户与下户.md](05-上户与下户.md) 同一套双校验。

### D. 退款强制节点

- 合同前退单：**退款流程设强制卡点，不删档期段走不完退款**——把「删档期」变成退款的必经路径；
- 删除动作由退款流程事件驱动，不是运营手工去清；
- 已上户的订单不可删段，只能收缩日期（历史留痕必须保留）。

### E. 换人对账专项（兜底网）

- 每日对账：**订单显示服务中但无对应上户中段** → 进对账清单（换人漏录的最后一道网）；
- 退款完成但档期段仍存在的 → 同类清单（见 [08-事后对账与抽检.md](08-事后对账与抽检.md)）。

## 三、责任角色

| 角色 | 责任 |
|---|---|
| 客服 | 换人需求发起与立案（产后更换客服牵头，运营组配合提供同级别资源） |
| 系统 | 接续段自动生成、退款硬卡点、空窗标注、对账清单 |
| 运营 | 换人资源协调、对账清单销项 |
| 月嫂老师 | 换人期间月嫂侧沟通与状态确认 |

## 四、指标

- **换人漏录 = 0**：对账清单「服务中无档期段」项残余条数；
- **退款未删档 = 0**：硬卡点上线后应为结构性 0；
- **离职/停单/爽约悬挂段 = 0**：对账清单「人已离职/停单但段未关闭」项残余条数；
- 换人接续时长（换人需求到 B 上户的小时数，业务目标 24h 响应 / 产后 72h 完成交接）；
- 交接空窗时长分布（识别交接流程瓶颈）。
