# 04 · 预产期漂移：最大单一失真源的专项治理

> **环节定位**：锁档/定档段的日期锚点是预产期，而预产期天然会漂移（提前/延后/医院改期）。失真链条是「客户生了/改期了 → 没人说 → 销售没改合同 → 档期虚挂」。**真正的信息源是客户，不是月嫂也不是销售**——本环节的核心是变「等人说」为「系统追」。
> **SLA**：发现即处理；窗口期每日主动追。
> **总览**：[00-总览.md](00-总览.md)

---

## 一、这个环节档期会怎么不准

| #   | 失真场景                   | 后果                       |
| --- | ---------------------- | ------------------------ |
| 1   | 客户提前/延后生了，没告诉公司        | 档期虚挂数天到数周，可售水位全错（最大单一因素） |
| 2   | 医院改了预产期，客户觉得「不是什么大事」没说 | 前 5 后 3 的档期范围整体错位        |
| 3   | 销售知道变更但改合同拖延           | 变更链路上任何一环拖几天，档期虚挂几天      |
| 4   | 预产期静默重算，受影响的锁定/定档没人重确认 | 连锁错误：日期变了人没变，撞上其他单       |

## 二、要做的事

### A. 窗口预警（把「客户忘了说」变成系统主动追）

- **进入预产期窗口（前 5 天）仍未上户的档期，每天自动推「待确认生产情况」**给销售和客服；
- 预警未处理逐级升级：T+2 未处理 → 客服主管；这同时是客户关怀触点，不是冷冰冰的催收。

### B. 客户触点（信息源激励）

- 待产关怀、产检提醒等**本来就要做的客户触达**，顺带一句「如有生产/改期请第一时间告诉我们」；
- **告知激励**：客户主动确认生产/改期的，给小激励（服务券/小礼品）——客户告知本身是值得买的，成本远低于档期虚挂的代价；
- 客户小程序可自助上报生产情况（一键，不填表）。

### C. 变更标准流程（禁止静默重算）

```
销售确认预产期变更
  → 档期自动按新预产期重算前 5 后 3
  → 受影响的锁档/定档单列清单，销售逐条重确认
  → 确认后生效，全程落流水
```

- 锁档/定档段日期「强制不可改」的唯一例外就是这条标准流程——口子只开这一个，且必须留痕。

### D. 锚点切换（只管到上户为止）

- 预产期锚点**只管锁档/定档阶段**；上户打卡后锚点切换为实际上户日，按订单天数重算结束日（见 [05-上户与下户.md](05-上户与下户.md)）——上户后预产期漂移不再影响档期。

### E. 漂移率统计（反哺缓冲带校准）

- 统计预产期变更率、平均漂移天数分布；
- 数据用于校准「前 5 后 3」缓冲带是否合理（漂移普遍大于 3 天就要重新评估缓冲带宽度），也用于识别变更高发客户群的特征。

## 三、责任角色

| 角色 | 责任 |
|---|---|
| 客户 | 第一信息源：生产/改期告知（激励 + 自助上报通道） |
| 销售 / 客服 | 预警处理、变更确认、合同变更及时办理 |
| 系统 | 窗口预警每日追、自动重算、受影响清单生成、流水留痕 |

## 四、指标

- **虚挂天数**（实际生产日 − 档期变更生效日）：目标趋近 0；
- 预警处理时长（预警发出到确认的中位数）；
- 变更重确认完成率（受影响档期逐条确认的完成度）；
- 预产期漂移率与漂移天数分布（长期监测）。

## 五、与其他环节的衔接

- 预警发现「已生产」→ 触发 [05-上户与下户.md](05-上户与下户.md) 的上户确认；
- 变更重算可能触发换人（预产期提前/延后是换人四触发之二）→ 接 [07-换人与退单.md](07-换人与退单.md)；
- 长期未确认的滞留状态进 [08-事后对账与抽检.md](08-事后对账与抽检.md) 每日对账清单。
