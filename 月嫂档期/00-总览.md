# 月嫂档期：准确与及时的环节化方案 · 总览

> **定位**：把「档期要准、要及时」拆成档期生命周期的 8 个环节 + 1 组横切机制，每个环节一个文件单独具体化。
> **口径关系**：状态语义（意愿三态 / 档期段五态 / 人态九态，含「停单」）以《月嫂运营/月嫂信息全维度记录.md》Sheet 20 为唯一权威，本文件夹不重复定义口径，只定义「每个环节做什么来保证准与及时」。
> **来源**：2026-08-26 讨论稿展开落盘。

---

## 一、先分清两件事：准确 ≠ 及时

| | 准确 | 及时 |
|---|---|---|
| 定义 | 系统显示的档期状态/日期与现实一致 | 现实变化到系统反映的时滞 |
| 敌人 | 「假」：口头承诺、飞单、忘了说、口径不一 | 「晚」：录入延迟、审批积压、日批滞后 |
| 危害排序 | **假比晚更可怕**——把不能卖的摆在货架上，水位虚高、超卖、推送空发 | 晚可以靠机制压缩，假只能靠规则和激励堵 |

**原则：不同环节用不同的尺子，先定 SLA 再谈手段。**

## 二、SLA 分层（各类变化的及时性要求）

| 变化类型 | 及时性要求 | 为什么 |
|---|---|---|
| 锁档 / 锁档释放 | 分钟级 | 防销售撞单，慢一分钟就可能重卖 |
| 上户 / 下户 | 打卡即时（当天级） | 直接决定可售池水位 |
| 请假生效 | 审批通过即时 | 叠加层优先级最高，覆盖即不可售 |
| 意愿状态 | 周级（7 天有效期倒逼） | 主观状态天然模糊，靠有效期与行为比对保鲜 |
| 长期锁档 / 恢复 | 天级（恢复确认 48h） | 低频高影响，走确认制 |
| 预产期变更 | 发现即处理（预警每日追） | 最大单一失真源，不能等人说 |

## 四、横切四杠杆（详见 [09-横切机制.md](09-横切机制.md)）

1. **信息源分级**：打卡 > 客户确认 > 月嫂申报 > 老师代录 > 销售录入，冲突时听前者的；
2. **诚实激励账**：档期不准的本质是「说真话的成本 > 收益」，逐角色重新定价；
3. **不新增维护动作**：把维护嵌进已有动作（打卡、护理日志、回访、签约、退款），凡是要求人多做一个动作的机制都会衰减；
4. **通道分级兜底**：订阅消息 → 短信 → 企微 → AI 外呼 → 人工电话，按事项紧急度选通道。

## 五、落地优先级（投入小见效快 × 堵最危险漏洞）

```
1. 每日对账清单（08）      → 只读不写，先把「多脏」变成可见数字
2. 预产期窗口预警（04）+ 定档只能从锁档产生（03） → 一个治最大的「晚」，一个治最大的「假」
3. 状态机收口（09·杠杆五）  → 地基工程，写入口唯一 + 全量流水
4. 打卡即档期（05）        → 及时性的终解，依赖收口先做完
5. 激励类机制（02）        → 见效慢但持久，与上面并行跑数据
```

**补一条冗余视角**：100% 准确不可能，稀缺高等级档期与其赌它准，匹配时默认做一备一预案——准确性管理和冗余设计是两条腿。
