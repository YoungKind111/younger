# 02 · 开档与意愿维护：解决「没人有动力维护」

> **环节定位**：管「想不想接」（意愿层）和「可售状态保鲜」。意愿和可售状态失真是通病，根因是**维护它对人没好处**——这个环节的核心是重造动力，不是加字段。
> **SLA**：意愿周级保鲜（7 天有效期倒逼）；推送确认分钟级回流。
> **口径**：意愿三态 + 有效期 + 可信度分以《月嫂运营/月嫂信息全维度记录.md》Sheet 5 / Sheet 20 为准。
> **总览**：[00-总览.md](00-总览.md)

---

## 一、这个环节档期会怎么不准

| # | 失真场景 | 后果 |
|---|---|---|
| 1 | 意愿不标 / 标不准，销售只能打电话问 | 匹配最大的时间黑洞，「点 10 个 8 个不接」 |
| 2 | 开了档实际不接（假开） | 可售表全是假水位，推送空发 |
| 3 | 意愿长期不更新，状态腐烂 | 销售按过期信息做判断，白打电话 |
| 4 | 合作类月嫂全开档但全不接 | 库存虚高（与 [01-建档入册.md](01-建档入册.md) 的标记联动） |

## 二、要做的事

### A. 意愿三态 + 有效期（硬口径）

- 三态：**真开放 / 可沟通 / 暂不接**，从未设置或过期自动回落「未标记」——「不维护」本身变成一个可见状态，而不是默认她还能接。
- **每次设置必须带期望上户时间**（6 个月内 / 6 个月后），有效期默认 7 天，修改即重置。

### B. 行为倒逼，不靠自觉

- 每次推送确认结果自动与自标意愿**逐次比对**，累计**意愿可信度分**：标「真开放」却连续拒单的分数掉、销售端列表降权。
- 「近 30 天推送响应」（如 5/5）直接展示在销售端人名列表里——**不靠教育标得准，靠数据识别谁标得准**。

### C. 让维护有即时回报

- 更新了意愿/档期的人**优先进入销售推送视野**（列表排序加权）——「维护 = 更多机会」必须让她感知到，否则机制撑不过三个月。
- 接档预登记（见 [06-服务中交叉验证.md](06-服务中交叉验证.md)）的人，下户前即进入推送视野，享受连档优先。

### D. 权限挂钩

- 长期未更新意愿 / 从不响应推送的人，限制抢单、报名权限——把「维护档期」变成接单资格的一部分。
- 培训中 / 长期锁档能看到抢单、不能报名；停单不可售（Sheet 20 规则 3）。

### E. 老师兜底核实

- 意愿失效超 3 天的 + 推送从不响应的 → 自动进**月嫂老师核实列表**，老师电话核实后代为更新（系统留「代更新」标记，与本人更新区分）。
- 核实动作嵌进既有触点：**上户回访挂电话前顺手在系统更新**，不新增维护动作。

### F. 触达通道

- 小程序卡片为主（一键设意愿，不填表）；
- 兜底：订阅消息 → 短信（只写「有一条档期邀约待确认」，不含薪资与客户姓名）→ 进老师核实列表。

## 三、责任角色

| 角色   | 责任                                 |
| ---- | ---------------------------------- |
| 月嫂   | 第一责任人：自己更新、更新错了担责（三项保证之一）          |
| 月嫂老师 | 担保名下月嫂状态准确 + 核实列表兜底处理              |
| 销售   | 打电话发现不对劲，系统上一键反馈，生成提醒给对应老师（双向反馈通道） |
| 系统   | 有效期自动失效、可信度分自动累计、核实列表自动生成          |
|      |                                    |

## 四、指标

- **意愿推送响应率**（推了回不回）——地基健康度；
- **意愿准确率**（说接的是不是真接）——MVP 验证的两个核心数字之一；
- 失效超 3 天残余条数（老师核实列表长度）；
- 可信度分分布（识别「标得准」人群占比）。

## 五、与其他环节的衔接

- 意愿是 [03-锁档与定档.md](03-锁档与定档.md) 候选人筛选的输入（暂不接/未标记不进推送圈选）；
- 可售库存统计口径 = 无锁档/定档/上户中段、未被请假覆盖、且意愿为真开放或可沟通（Sheet 20 关键语义约定 3）；
- 上户中的意愿维护走 [06-服务中交叉验证.md](06-服务中交叉验证.md) 的预登记通道。
