# 03 · 锁档与定档：堵住「系统外承诺」

> **环节定位**：交易环节的档期防「假」——一切承诺过系统，口头锁档、囤人、凭空定档在这个环节被规则堵死。
> **SLA**：锁档 / 释放**分钟级**（防撞单）；定档事件驱动即时。
> **口径**：档期段五态、锁档绑订单 + 48h、定档两来源（有效锁档转化 / 绑定时订单已签合同直设），以 Sheet 20【档期状态流转表】为准。
> **总览**：[00-总览.md](00-总览.md)

---

## 一、这个环节档期会怎么不准

| # | 失真场景 | 后果 |
|---|---|---|
| 1 | 口头锁档不进系统：电话里答应了客户，系统没锁，别人又推出去 | 撞单——对客户失信，对月嫂失约 |
| 2 | 销售囤人：先锁着慢慢谈 | 可售池被抽干，其他人无货可卖 |
| 3 | 凭空定档：系统里直接空降定档段 | 绕开全部规则，档期来源不可追溯 |
| 4 | 多销售轰炸同一个月嫂 | 月嫂被骚扰，确认口径互相矛盾 |
| 5 | A 客户锁完 B 客户锁、售后轮着锁 | 档期长期被无效占用，真实可售被低估 |

## 二、要做的事

### A. 软锁前置（全链路系统内完成）

- 推送确认 → **锁档**（绑定订单 ID + 48 小时有效期）→ 定档，全链路在系统内完成，没有系统外的位置；**一个订单可同时锁多名候选月嫂**，先到先得，一人转定档其余自动释放；
- **订单已签合同的绑定**（售后换人补位等）：**运营直排 → 直接定档**，无需月嫂确认、不占 48 小时锁档位——合同先于绑定存在，锁档仪式为空转；**直排无需确认的前置条件：合同为三方合同**（平台/客户/月嫂），月嫂是签署方之一，签约即知情，不存在「被定档却不知情」；
- **先建单、后锁人**：锁定时订单必然已存在，不存在「先锁人后建单」的场景（业务已确认）。

### B. 五条硬规则（状态机强制，不靠自觉）

1. **锁档必须绑定订单 ID + 有效期**（默认 48 小时），过期系统自动释放回可售池——销售想囤也囤不住；**一个订单可同时锁档多个月嫂**（候选锁位，先到先得），一个月嫂同一时间只能被一个订单锁定；
2. **定档两来源，但必须有已签合同**：① 有效锁档转化（合同生效/客户确认）；② 绑定订单时订单合同已签 → **直接定档**（合同先于绑定存在，如售后换人补位，无需先锁档）。无论哪条路径，人工不得凭空定档——从源头堵死「系统外承诺、系统里空降」；
3. **锁档创建即按预产期前 5 后 3 确定日期范围**（预产期取自合同），直接定档同规则，之后强制不可改；预产期变更走 [04-预产期漂移.md](04-预产期漂移.md) 的标准流程重算；
4. **定档一生、余锁尽释**：任一月嫂转定档（任一路径）后，同订单其余锁档自动释放回可售池，不等 48 小时过期；
5. **段间不重叠**（2026-08-26）：同一月嫂的档期段日期不得重叠（请假叠加层除外）——新段创建时系统校验：锁档/定档段之间**硬拦截**；与上户中段的未来预估重叠给**软警告**（允许锁定，提示关注提前下户可能）；连档首尾相接（前段结束日 = 后段开始日）不视为重叠。

### C. 防撞单与协同

- 已锁的人在其他人列表显示「XX 已锁」，不可再推；同一订单的多个候选锁位互相可见（谁锁的、几时过期）；
- 已在沟通中的人，其他销售可发系统内消息询问进展——把销售自发的「一人找、大家用」协同机制系统化；
- 客户侧自助锁单 + 锁定时长（回应「锁单乱象」诉求）：锁多久、给谁锁的，全程透明。

### D. 定档事件驱动

- 合同生效 / 客户确认事件自动触发锁档→定档流转，**不依赖人记得去点**；
- 每次流转落 `maternityNannyAuditLog` 流水——撞单争议不用翻聊天记录，谁改的、为什么是这样，随时可查。

### E. 推送→确认→锁定的衔接

- 销售圈选 → 推送档期卡片（订单摘要 + 确认时限：空闲默认 4h，可选 2/4/24）→ 月嫂点「我能接」→ 列表变绿可锁定；
- 上户中月嫂时限差异化（默认 12h + 定时投递），见 [06-服务中交叉验证.md](06-服务中交叉验证.md)。

### F. 锁档生命周期善后：过期与续锁（2026-08-26）

- **过期释放的订单侧闭环**：锁档 48h 过期 → 系统自动通知发起销售「锁档已过期」，订单回「待匹配」重新进圈选；原月嫂回可售池，未响应记录照记（影响意愿可信度）；
- **续锁规则（防变相囤人）**：允许对同一月嫂续锁，但**同一订单对同一月嫂最多连续锁 2 次**（48h×2 = 96h 封顶）；第 2 次过期后进入 **24 小时冷却期**，期内该订单不可再锁她——给「客户还在考虑」一次缓冲，封死无限续锁（⚠️ 次数与冷却时长为建议参数，待业务确认）；
- 同一订单改锁他人不受冷却限制（候选锁位规则见 B-1）。

## 三、责任角色

| 角色 | 责任 |
|---|---|
| 销售 | 发起锁定、对锁定真实性负责（锁了不签 = 占用库存，可见） |
| 系统 | 硬规则校验、过期自动释放、事件驱动流转、全量流水 |
| 运营组 | 已签合同订单的直排定档（路径②，无需月嫂确认） |
| 月嫂 | 限时确认（我能接 / 接不了 / 想聊聊） |

## 四、指标

- **撞单率 = 0**（Q3 目标）；
- **无合同定档 = 0**：状态机拦截的非法定档尝试（无已签合同）次数（应为 0，>0 说明有入口没收干净）；
- **余锁释放及时率 = 100%**：定档产生后同订单其余锁档自动释放（系统自动，无人工动作）；
- **续锁超限 = 0**：超过「同一人连锁 2 次 + 冷却期」的锁定尝试应被拦截；
- 重叠校验拦截次数（监控入口数据质量，高=上游流程有问题）；
- 锁档过期释放及时率（应 = 100%，系统自动）；
- 锁档→定档转化率（衡量锁定质量，过低说明销售在滥锁）。
