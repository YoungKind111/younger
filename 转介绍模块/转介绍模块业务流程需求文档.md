# 转介绍模块 — 业务流程需求文档

> 基于 `referrer-list.html`、`referral-lead.html`、`commission.html`、`rule-config.html` 四个页面原型提炼

---

## 一、业务角色

| 角色 | 职责 |
|---|---|
| 销售/客服 | 登记转介绍客户、提交佣金申请 |
| 部门负责人 | 审核本部门发起的佣金申请 |
| 销售负责人 | 审核销售合规性 |
| 运营负责人 | 审核服务质量相关事项 |
| 会计 | 核对金额、账户信息准确性 |
| 财务负责人 | 审核付款合理性与资金安排 |
| 总经理 | 终审批准 |
| 出纳 | 执行网银/柜台转账并确认 |
| 系统管理员 | 维护佣金计算规则参数 |

## 三、流程详解

### 3.1 推荐人建档流程

```
【入口】推荐人档案页

Step 1: 新增推荐人
  └─ 填写基本信息：姓名、手机号、身份证号、推荐人类型（老客户/月嫂）
  └─ 填写银行账户：开户行、支行、收款账号、户名
  └─ 系统生成推荐人档案，状态为「有效」

Step 2: 信息维护
  └─ 可编辑：身份证号、推荐人类型、银行账户信息
  └─ 不可编辑（只读）：姓名、手机号（提示：在客户管理或月嫂档案界面编辑）
  └─ 可查看详情：基本信息 + 银行账户 + 历史成功签约客户列表

Step 3: 档案查看
  └─ 列表展示：姓名、手机号、类型、累计推荐、成功签约、累计佣金
  └─ 详情弹窗展示该推荐人所有成功签约客户的佣金明细与状态
```

**关键规则：**
- 推荐人类型分为「老客户」和「月嫂」两类，影响后续佣金计算规则
- 银行账户信息为佣金打款的必要前置条件

---

### 3.2 转介绍订单登记流程

```
【入口】转介绍订单页

Step 1: 登记客户
  └─ 填写客户姓名、手机号
  └─ 选择推荐人（下拉选择已有档案）
  └─ 选择介绍类型（客户介绍/月子转介绍）
  └─ 选择意向分店、归属销售
  └─ 客户状态默认为「未签约」
  └─ 系统生成订单编号

Step 2: 状态变更 — 未签约 → 已签约
  └─ 编辑订单，将客户状态改为「已签约」
  └─ 补充签约信息：合同金额、套餐天数、签约日期
  └─ 状态变更后，系统自动生成佣金记录（状态为「未申请」）
```

**关键规则：**
- 未签约状态的客户不显示签约金额、天数、日期
- 已签约后自动触发佣金计算，按规则引擎匹配对应佣金金额

---

### 3.3 佣金自动计算流程

```
【触发条件】订单状态变为「已签约」

Step 1: 天数门槛校验
  └─ 若 serviceDays < minDays（默认7天）：无效单，佣金=0，不计入累计单数
  └─ 若 serviceDays ≥ minDays：进入下一步规则匹配

Step 2: 推荐人类型分支

  ├─ 分支 A：月嫂介绍
  │   └─ 佣金 = 成交金额 × nurseRate（默认10%）
  │   └─ 不区分套餐类型和阶梯
  │
  └─ 分支 B：客户介绍
      ├─ 子规则1：短天数区间 [shortDaysStart, shortDaysEnd]（默认7~12天）
      │   └─ 佣金 = shortDaysAmount（默认100元）
      │
      ├─ 子规则2：特价套餐且 days ≥ specialDays（默认≥13天）
      │   └─ 佣金 = specialCommission（默认200元）
      │
      └─ 子规则3：常规套餐（含未达specialDays的特价套餐）
          ├─ 累计第1单：固定 step1Amount（默认200元）
          ├─ 累计第2~3单：成交金额 × step2to3Rate（默认3%）
          ├─ 累计第4~5单：成交金额 × step4to5Rate（默认4%）
          └─ 累计第6单及以上：成交金额 × step6PlusRate（默认5%）

Step 3: 输出结果
  └─ 命中规则标签（如「第1单固定200元」「月嫂推荐10%」等）
  └─ 税前佣金金额
  └─ 累计单数+1
```

---

### 3.4 佣金申请流程

```
【入口】佣金结算页

方式一：单笔申请
  └─ 操作列点击「申请」按钮
  └─ 确认弹窗：展示推荐人、客户、佣金金额
  └─ 确认后生成申请单（requestNo），状态变为「审批中」

方式二：批量申请
  └─ 勾选多条「未申请」状态记录（同一推荐人可聚合）
  └─ 点击「批量申请」
  └─ 预览弹窗：按推荐人聚合显示笔数、合计税前佣金、银行信息
  └─ 确认后：同一推荐人自动生成一个 requestNo，状态批量变为「审批中」

申请单生成规则：
  └─ requestNo 格式：FY + YYYYMMDD + 3位序号（如 FY20251209001）
  └─ 申请人：当前操作用户（如「黄敏仪（销售部北滘）」）
  └─ 申请时间：当前系统时间
  └─ 初始审批记录：提交节点自动写入
```

---

### 3.5 多节点审批流程

```
【审批流】7个节点，串行审批，任一节点「不通过」则整单驳回

  节点1: 提交（系统自动）
    ↓
  节点2: 发起人部门负责人（张三）
    ↓ 通过
  节点3: 销售负责人（植亚来）
    ↓ 通过
  节点4: 运营负责人（梁艳红）
    ↓ 通过
  节点5: 会计审核（何才连）
    ↓ 通过
  节点6: 财务负责人审核（尹俊）
    ↓ 通过
  节点7: 总经理审核（卓大龙）
    ↓ 通过
  状态变为「已通过」，paymentStatus 变为「待打款」

【驳回场景】
  任一节点点击「拒绝」→ 填写驳回备注 → 整单状态变为「已驳回」
  同一 requestNo 下的所有记录同步变为「已驳回」

【数据联动】
  同一 requestNo 下的多条佣金记录共享审批状态
  审批记录追加到每条关联记录的 approvalRecords 中
```

**审批操作界面：**
- 当前审批节点弹窗：显示当前节点名称、审批人
- 底部双按钮：「拒绝」（红色）/「通过」（蓝色）
- 必填备注（驳回时强制要求填写）

---

### 3.6 打款流程

```
【触发条件】审批状态 = 「已通过」且 打款状态 = 「待打款」

Step 1: 点击「打款」按钮
  └─ 弹窗展示：推荐人信息、收款银行、账号、户名
  └─ 展示税前金额

Step 2: 代扣个税计算
  └─ 系统默认值：
      ├─ 若 佣金 ≤ 800元：taxAmount = 0（免税）
      └─ 若 佣金 > 800元：taxAmount = (佣金 - 800) × 20%
  └─ 允许手动修改个税金额（应对特殊情况）
  └─ 税后实发 = 税前金额 - 代扣个税（实时联动计算）

Step 3: 填写打款信息
  └─ 凭证号：网银流水号或柜台凭证号（必填）
  └─ 打款备注（选填）

Step 4: 确认已打款
  └─ 同一 requestNo 下所有「已通过+待打款」记录同步更新：
      ├─ paymentStatus → 「已打款」
      ├─ taxAmount、actualAmount、voucherNo
      ├─ payTime（当前时间）、payer（当前用户，如「出纳小李」）
      └─ approvalRecords 追加「出纳打款」节点记录
```

---

### 3.7 佣金规则配置流程

```
【入口】佣金规则配置页

Step 1: 参数配置
  └─ 天数门槛规则：无佣金天数门槛、短天数区间起止、短天数固定佣金
  └─ 特价套餐规则：价格标准、天数标准、固定佣金
  └─ 常规阶梯规则：第1单固定金额、第2~3单比例、第4~5单比例、第6单+比例
  └─ 月嫂规则：月嫂佣金比例
  └─ 表单校验：短天数区间结束值 < 特价套餐天数标准（防止区间交叉）

Step 2: 保存配置
  └─ 校验通过后保存，全局生效

Step 3: 规则测试（可选）
  └─ 输入模拟参数：累计单数、推荐人身份、套餐类型、天数、成交金额
  └─ 运行测试 → 输出：是否有效单、命中规则、累计后单数、税前佣金金额
```

## 四、状态机

### 4.1 审批状态流转

```
                    ┌─────────────┐
                    │   未申请    │ ←──────────────┐
                    └──────┬──────┘                │
                           │ 申请/批量申请          │
                           ▼                       │
                    ┌─────────────┐                │
           ┌───────│   审批中    │───────┐        │
           │       └──────┬──────┘       │        │
           │ 驳回          │ 通过        │        │
           ▼               ▼             │        │
    ┌─────────────┐  ┌─────────────┐    │        │
    │   已驳回    │  │   已通过    │────┘        │
    └─────────────┘  └──────┬──────┘             │
                            │ 打款               │
                            ▼                    │
                     ┌─────────────┐             │
                     │   已打款    │─────────────┘（重新申请需生成新单）
                     └─────────────┘
```

### 4.2 打款状态流转

```
未打款 → 待打款 → 已打款
  │        │
  └────────┘（审批驳回时打款状态保持「未打款」）
```

## 五、关键业务规则汇总

| 规则项 | 默认值 | 说明 |
|---|---|---|
| 无佣金天数门槛 | 7天 | 低于7天不计单、无佣金 |
| 短天数区间 | 7~12天 | 固定100元 |
| 特价套餐天数标准 | ≥13天 | 价格标准9980元，固定200元 |
| 常规第1单 | 200元 | 固定金额 |
| 常规第2~3单 | 3% | 成交金额比例 |
| 常规第4~5单 | 4% | 成交金额比例 |
| 常规第6单+ | 5% | 成交金额比例 |
| 月嫂佣金 | 10% | 成交金额比例，不区分阶梯 |
| 个税起征点 | 800元 | ≤800免税，超出部分20% |
| 累计单数 | 按推荐人维度 | 区分月嫂/客户两种类型分别累计 |

## 六、异常处理

| 异常场景 | 处理方式 |
|---|---|
| 审批驳回 | 同一 requestNo 下所有记录同步驳回，可重新提交申请（生成新 requestNo） |
| 银行信息不全 | 审批节点可驳回，要求补充支行/账号信息 |
| 规则参数冲突 | 保存时表单校验，短天数结束值必须 < 特价套餐天数标准 |
| 批量申请跨推荐人 | 系统自动按推荐人分组成多个 requestNo |
| 个税手动修改 | 允许出纳手动调整，系统自动重算实发金额 |
