## 一、业务场景总览

| 参与方 | 角色说明 | 典型身份 |
|--------|----------|----------|
| **A（被推荐人）** | 月嫂/护理人员，最终提供服务的人 | 报名培训的月嫂、在岗阿姨 |
| **B（推荐人/推广人）** | 推荐 A 加入平台的人 | 培训机构、公司员工、在岗月嫂 |
| **C（另一推荐人）** | 试图挖走 A 的另一推荐人 | 其他培训机构、其他月嫂 |
| **渠道运营/招生部门** | 后台管理人员 | 公司内部运营、渠道开发人员 |

**核心商业模式**：
- B 推荐 A 加入平台 → A 完成报名 → A 被客户匹配并签署服务合同 → A 实际上户服务
- B 获得基于 **合同金额 × 配置比例** 的奖励（非固定金额）
- 奖励按 **A 的实际上户次数** 结算，有次数上限
- 支持 **二级分销**：渠道/员工（一级）→ 月嫂（二级）→ 新月嫂（被推荐人）

## 二、关键规则定义

### 2.1 佣金计算规则（重大调整）

**原设计**：固定金额制（线索¥10 / 签约¥200 / 上户¥500）  
**现调整为**：比例提成制（仅支持比例提成，固定金额已移除）

```
单次上户奖励 = 该次服务合同金额 × 系统配置比例

示例：
  A 月嫂某次上户合同金额 = 15,000 元
  系统配置比例 = 0.5%
  B 获得奖励 = 15,000 × 0.5% = 75 元
```

**配置项**：

| 配置项 | 说明 | 默认值 | 可配置范围 |
|--------|------|--------|------------|
| 奖励比例 | 合同金额 × 比例 = 奖励金额 | 0.5% | 0.1% ~ 5% |
| 奖励次数上限 | 同一被推荐人最多产生多少次奖励 | 5 次 | 2 ~ 10 次 |
| 结算节点 | 什么时候算"完成"可结算 | 已下户后结算 | 固定，不可配置 |

> 结算节点固定为"已下户后结算"，所有佣金均在服务周期结束、客户确认后统一结算。

---

### 2.2 绑定关系规则

#### 绑定建立
- B 向 A 发送专属推广链接 / 小程序码 → A 完成报名 → A 绑定到 B 名下
- 绑定关系一旦建立，**不可由 A 主动切换**

#### 绑定有效期（自动解绑）
```
规则：A 绑定到 B 名下后，若 X 个月内 A 没有任何上户记录，则自动解绑

配置项：
  解绑期限：默认 6 个月（可配置范围：3 ~ 12 个月）
  
解绑后：
  - A 变为"自由人"，可被其他推荐人重新绑定
  - B 不再获得 A 后续上户的任何奖励
  - 历史已产生的奖励不受影响
```

#### 绑定冲突处理（First-Touch 原则）
```
场景：A 已绑定在 B 名下，C 向 A 发链接试图重新绑定

处理：
  ① A 点击 C 的链接 → 系统检测到 A 已有绑定关系（B）
  ② 提示 A："您已被 B 推荐，无需重复绑定"
  ③ C 的后台不显示 A 为其被推荐人
  ④ A 的归属保持为 B，直至绑定过期解绑或被运营人工调整

例外：
  - 若 A 与 B 的绑定已过期解绑 → A 可重新被 C 绑定
  - 若运营人员在后台手动解绑 A→B → A 可重新被绑定
```

---

### 2.3 二级分销规则

#### 分销层级定义

```
一级分销商（渠道/员工）
  └── 二级分销商（月嫂/阿姨）
        └── 被推荐人（新月嫂）
```

**典型场景**：
- 招生部门员工小李 → 发展了一批月嫂 → 月嫂张阿姨 → 张阿姨推荐了自己的姐妹王姐
- 培训机构"金牌家政" → 旗下有 50 名月嫂 → 月嫂刘阿姨 → 刘阿姨介绍了同乡赵妹

#### 佣金分配规则

```
当二级分销产生上户奖励时：

总佣金 = 合同金额 × 配置比例

分配方式：
  一级拿 X%，二级拿 Y%，一级 + 二级 = 100%，无平台保留

默认示例：
  合同金额 15,000 元，比例 0.5%，总佣金 75 元
  一级（员工小李）拿 80% = 60 元
  二级（月嫂张阿姨）拿 20% = 15 元
```

**一级分销商的特殊权益**：
- 管理看板：可查看自己发展的所有二级分销商及其业绩
- 不参与具体被推荐人的绑定关系，只参与佣金分成

## 三、状态流转更新

### 3.1 被推荐人（A）全生命周期状态

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  未注册  │───▶│ 已报名  │───▶│ 已签约  │───▶│ 已上户  │
│         │    │（待审核）│    │（待服务）│    │（服务中）│
└─────────┘    └─────────┘    └─────────┘    └────┬────┘
                                                   │
                                                   ▼
                                             ┌─────────┐
                                             │  已下户  │
                                             │（可结算）│
                                             └─────────┘
```

**各状态定义**：
- **已报名**：A 填写了报名表，提交了基本信息
- **已签约**：A 与公司签署了合作协议
- **已上户**：A 实际到岗开始服务
- **已下户**：服务周期结束，客户确认完成

**现金结算节点**：默认"已下户"时计算佣金，进入待结算池

> **注**：实际小程序端（h5-profile.html）中展示的状态为：已报名 / 已签约 / 已上户 / 已下户。

### 3.2 推广人（B）佣金看板

```
推广人 B 打开 小程序推广中心，看到：

【本月推荐排行】按推荐人数/收益排名（名字脱敏展示）
【快捷入口】分享海报 / 奖励规则
【我的被推荐人】（在个人中心查看）
   - 张阿姨：已上户 3 次（剩余奖励次数 2 次）
   - 李姐：已签约，待上户
   - 王妹：已报名，待签约
```

## 四、后台配置项汇总

### 4.1 全局参数配置（新增模块）

| 配置项 | 当前值 | 可配置范围 |
|--------|--------|------------|
| 佣金计算方式 | 比例提成 | ~~固定金额 /~~ 比例提成（仅比例提成） |
| 佣金比例 | 0.5% | 0.1% ~ 5% |
| 单次被推荐人奖励次数上限 | 5 次 | 2 ~ 10 次 |
| 结算节点 | 已下户后结算 | 固定，不可配置 |
| 绑定有效期 | 6 个月 | 3 ~ 12 个月 |
| 二级分销开关 | 开启 | 开启 / 关闭 |
| 一级分销分成比例 | 80% | 0% ~ 100% |
| 二级分销分成比例 | 20% | 0% ~ 100% |
| 一级+二级 | 必须 = 100% | 无平台保留 |


### 4.2 渠道级可覆盖配置

- 佣金比例（某渠道可单独设为 1%，其他渠道 0.5%）
- 奖励次数上限（转介绍渠道可设为 10 次，其他渠道 5 次）
- 规则状态（手动开关控制是否生效，替代原生效/失效时间）

## 五、异常场景处理

### 5.1 A 被推荐后长期无进展
```
场景：A 报名后长期无进展（如 3 个月未签约），或签约后 6 个月无上户

处理：
  - 系统标记 A 为"沉睡用户"
  - 通知 B："您推荐的张阿姨已 3 个月未签约，可提醒她尽快跟进"
  - 若超过绑定有效期（6个月）仍无上户 → 自动解绑
  - 解绑前 7 天通知 B："张阿姨即将到期解绑，如她近期有上户计划请尽快跟进"
```

### 5.2 A 上户后客户退单
```
场景：A 已上户服务，但客户中途退单/换人

处理：
  - 若退单发生在"已下户"前：
    - 该次服务不计入 B 的奖励次数
    - 该次服务不产生佣金
  - 若退单发生在"已下户"后：
    - 奖励已生效，不追回（视为正常完成）
```

### 5.3 A 的第 N 次上户超过奖励次数上限
```
场景：配置奖励上限 5 次，A 已完成 5 次上户，第 6 次上户

处理：
  - B 不再获得该次现金奖励
  - 系统通知 B："张阿姨已完成 5 次上户奖励上限，后续上户不再产生现金奖励"
```

### 5.4 二级分销中的 A 也发展了下级
```
场景：A 是被推荐人，同时 A 也是二级分销商，A 推荐了 C

处理：
  - A 作为被推荐人：A 的上户给 B（一级）和 A 的上级渠道带来佣金
  - A 作为推荐人：C 的上户给 A 和 A 的上级渠道带来佣金
  - A 的双重身份不冲突，业绩分别计算
```
