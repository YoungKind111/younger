## 一、推广归因流程（全链路追踪）

### 1.1 流程概述
被推荐人通过各种触点接触到推广信息，系统需要准确识别其来源推广人，并在后续转化节点（报名 → 签约 → 上户）自动计算佣金。

### 1.2 正常流程（微信小程序环境）

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  推广人获取  │     │  被推荐人   │     │  系统追踪   │     │  报名表单   │
│  推广物料   │────▶│  扫码/分享  │────▶│  openId     │────▶│  自动关联   │
│ (小程序码/  │     │  卡片进入   │     │  映射推广人  │     │  推广人信息 │
│  分享卡片)  │     │             │     │  写入Storage│     │             │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

**步骤详解：**

| 步骤 | 触发方 | 系统行为 | 数据记录 |
|------|--------|----------|----------|
| 1 | 推广人 | 系统生成专属小程序码/分享卡片（含 `scene` 参数，如 `r=推广人ID`） | 推广人ID、渠道ID |
| 2 | 被推荐人 | 微信内扫码或点击分享卡片，进入小程序报名页 | 扫码时间、微信openId |
| 3 | 小程序 | `onLoad` 解析 `scene` 参数，提取 `referrer`（推广人ID），调用 `wx.setStorageSync` 存入本地 | `referrer`、写入时间 |
| 4 | 被推荐人 | 浏览报名页面，小程序从 Storage 读取推广人信息 | 页面访问记录 |
| 5 | 系统 | 表单页面自动填充隐藏字段（推广人ID），报名表提交时携带 | 推广人ID预填 |
| 6 | 服务端 | 以被推荐人 `openId` 为键，将推广人ID写入「openId-推广人映射表」 | 建立长期绑定关系 |
| 7 | 被推荐人 | 提交报名表，系统读取映射表完成归属记录 | 报名表关联推广人ID |

> **技术要点：**
> - `scene` 参数长度限制为 32 个字符，需对推广人ID进行短码映射（如将长ID映射为 6~8 位短码）
> - `wx.setStorage` 数据在小程序卸载前持久保存，归因有效期不受浏览器 Cookie 限制
> - 同一微信用户（同一 `openId`）无论多少次卸载重装，服务端映射表始终保留绑定关系
> - 分享卡片使用 `Page.onShareAppMessage` 动态注入 `path: '/pages/register/form?referrer=xxx'`

### 1.3 归因规则判定逻辑

```
被推荐人提交报名表时，系统按以下优先级判定归属：

1. 【最高】小程序 Storage 中的 referrer
   └── 如果 wx.getStorageSync('referrer') 存在且对应推广人有效 → 归属该推广人
   └── 如果 Storage 中无 referrer 或推广人无效 → 继续向下判定

3. 【再次】服务端 openId 映射表
   └── 如果该被推荐人的 openId 已绑定过推广人 → 归属历史绑定推广人
   └── 如果未绑定过 → 继续向下判定

4. 【最低】手动选择/填写"谁推荐你来的？"
   └── 如果被推荐人手动填写了推荐人信息 → 归属该推荐人
   └── 如果以上全部未命中 → 标记为"自然流量"，不计入任何推广人

绑定关系建立后：
  - A（被推荐人）完成报名 → 系统以 A 的 openId 为键，建立 A→B（推广人）映射关系
  - 映射关系一旦建立，长期有效（除非人工解绑）
  - 绑定有效期内，A 的任何后续转化（签约/上户）均自动关联到 B
```

### 1.4 归因冲突处理

| 场景 | 处理规则 |
|------|----------|
| 同一被推荐人多次访问不同推广人的链接/小程序码 | 以**首次有效绑定**为准（First-Touch），绑定后不可切换 |
| 被推荐人已报名（无归属），后续通过推广链接再次访问 | 从 Storage 读取 referrer 重新归因，不受 30 天窗口期限制 |
| 被推荐人已报名且已有归属，后续通过其他推广链接访问 | **保持原归属不变**，系统提示"您已被 B 推荐" |
| 被推荐人解绑后，通过其他推广链接访问 | 视为自由人，可被新的推广人重新绑定 |
| 同一微信用户多个手机号报名 | 以 openId 为唯一标识，同一 openId 只能绑定一个推广人；不同手机号但同一 openId 视为同一被推荐人 |
| 跨设备访问（A 手机扫码，B 手机报名） | 同一微信账号 openId 一致，服务端映射表保证归因连续；更换微信账号视为新用户 |

### 1.5 推广物料机制

```
推广物料类型：
  1. 小程序码（带 scene 参数）
     - 生成方式：调用 wxacode.getUnlimited，scene 中携带短码化的推广人ID
     - 适用场景：线下海报、朋友圈图片、微信群传播
     - 限制：scene 最大 32 字节，需做短码映射

  2. 分享卡片（onShareAppMessage）
     - 生成方式：推广人点击「分享海报」→ 小程序动态生成卡片，path 中携带 referrer
     - 适用场景：微信好友一对一分享、微信群分享
     - 优势：可自定义标题/图片，体验原生
```

## 二、推广人注册与审核流程

### 2.1 两种注册路径

```
路径A：小程序自助注册（外部推广人员）
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 推广人访问  │     │ 填写注册资料 │     │ 注册成功    │
│ 小程序注册页面  │────▶│ (手机号/    │────▶│ 获得专属推广 │
│             │     │  验证码/    │     │ 物料，开始  │
│             │     │  协议勾选)  │     │ 推广        │
└─────────────┘     └─────────────┘     └─────────────┘

> **注**：注册时无需填写真实姓名、身份证号、银行卡等信息，这些信息在首次提现时配置即可。

路径B：后台直接添加（内部运营人员）
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 运营人员进入 │     │ 填写推广人  │     │ 直接生成    │
│ 后台添加页面 │────▶│ 基本信息    │────▶│ 专属推广物料 │
│             │     │             │     │ 立即生效    │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 2.2 推广人状态流转

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   注册成功   │────▶│   正常状态   │────▶│   已冻结    │
│  (registered)│     │  (active)   │     │  (frozen)   │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                │
                                                ▼
                                         ┌─────────────┐
                                         │   已解冻    │
                                         │  恢复正常   │
                                         └──────┬──────┘
                                                │
                                                ▼
                                         ┌─────────────┐
                                         │   正常状态   │
                                         │  (active)   │
                                         └─────────────┘
```

### 2.3 状态说明

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| **注册成功** | 推广人完成注册，系统自动生成推广物料 | 自助注册提交成功 / 后台添加成功 |
| **正常** | 推广人可正常推广、获得佣金 | 注册成功后的默认状态 |
| **冻结** | 停止生成新佣金，保留已有余额 | 运营人员手动冻结（如发现异常行为） |
| **解冻** | 恢复正常推广和佣金计算 | 运营人员手动解冻 |

## 三、佣金计算与结算流程

### 3.1 佣金计算时机

```
被推荐人状态变更时触发佣金计算：

报名 ─────────────────────────────────────────────▶
    │                                                   │
    ▼                                                   │
┌─────────────┐                                        │
│ 状态：已报名 │── 记录推广归属，通知推荐人跟进           │
│             │                                        │
└──────┬──────┘                                        │
       │                                                │
       ▼                                                │
┌─────────────┐                                        │
│ 状态：已签约 │── 记录预计佣金（合同金额 × 比例）        │
│ (signed)    │                                        │
└──────┬──────┘                                        │
       │                                                │
       ▼                                                │
┌─────────────┐                                        │
│ 状态：已上户 │── 通知推荐人上户成功                     │
│ (worked)    │                                        │
└──────┬──────┘                                        │
       │                                                │
       ▼                                                │
┌─────────────┐                                        │
│  已下户    │── 佣金正式可结算（进入待结算池）         │
│ (completed) │── 检查奖励次数是否已达上限               │
└─────────────┘                                        │
                                                       │
◀──────────────────────────────────────────────────────┘
                    每月1-5日、15-20日开放提现
```

### 3.2 佣金计算公式

```
单笔佣金 = 合同金额 × 佣金比例 × (1 + 星级加成比例)

其中：
  合同金额 = 该次服务的客户合同金额
  佣金比例 = 系统配置比例（默认 0.5%，渠道可覆盖）
  星级加成比例 = 推广人当前星级对应的百分比（1星0%，2星5%，3星8%，4星10%，5星15%）

检查项：
  - 该被推荐人历史已结算次数 < 奖励次数上限 → 正常计算
  - 该被推荐人历史已结算次数 ≥ 奖励次数上限 → 现金佣金 = 0，不再产生奖励

示例计算（比例提成模式）：
  推广人：4星推广人（+10%）
  渠道：老带新转介绍（比例 0.5%）
  A 月嫂合同金额：15,000 元
  
  该笔佣金 = 15,000 × 0.5% × (1 + 10%) = 75 × 1.1 = 82.5元

二级分销分配示例：
  总佣金 82.5 元，一级分成 80%，二级分成 20%，一级+二级=100%，无平台保留
  一级（渠道/员工）= 82.5 × 80% = 66 元
  二级（月嫂推荐人）= 82.5 × 20% = 16.5 元
```

### 3.3 佣金状态流转

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  待结算   │───▶│  可提现   │───▶│  提现中   │───▶│  已到账   │
│(pending) │    │(available)│    │(withdrawing)│   │(paid)   │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
       │
       ▼
┌──────────┐
│  打款失败 │
│(failed)  │
└────┬─────┘
     │
     ▼
┌──────────┐
│  退回余额 │
│(refunded)│
└──────────┘
```

**状态说明：**
- **待结算**：订单已完成，佣金已计算，等待结算
- **可提现**：已过结算等待期，推广人可申请提现
- **提现中**：推广人提交提现申请，正在处理
- **已到账**：款项已成功到达推广人账户
- **打款失败**：银行卡打款失败（卡号错误、户名不符等）
- **退回余额**：打款失败后，将金额退回推广人余额账户

## 四、提现流程

### 4.1 推广人端提现流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 推广人进入  │     │ 确认到账    │     │ 确认提现    │     │ 系统校验    │
│ 佣金钱包    │────▶│ 银行卡信息  │────▶│ 金额（全部）│────▶│ 余额/时间/  │
│             │     │ (姓名/身份证│     │             │     │ 银行卡信息  │
│             │     │  /开户行/   │     │             │     │             │
│             │     │  银行卡号)  │     │             │     │             │
└─────────────┘     └─────────────┘     └─────────────┘     └──────┬──────┘
                                                                    │
                    ┌───────────────────────────────────────────────┘
                    │ 校验通过
                    ▼
             ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
             │ 提交提现申请 │────▶│ 系统扣除    │────▶│ 进入打款    │
             │             │     │ 余额        │     │ 处理队列    │
             └─────────────┘     └─────────────┘     └─────────────┘
```

### 4.2 提现校验规则

| 校验项 | 规则 | 失败提示 |
|--------|------|----------|
| 最低提现额 | ≥ 50 元 | "最低提现金额为 50 元" |
| 可提现时间 | 每月 1-5 日、15-20 日 | "当前不在提现开放期" |
| 账户状态 | 推广人状态为"正常" | "账户已冻结，无法提现" |
| 银行卡信息 | 必须绑定有效银行卡（姓名/身份证/开户行/卡号） | "请先绑定银行卡" |

> **注**：提现时必须将全部可提现余额一次性提现，不支持部分提现。银行卡信息在首次提现时配置，无需独立的实名认证流程。

### 4.3 税费处理

```
单月佣金累计 ≤ 800 元：免税
单月佣金累计 > 800 元：
  
  应纳税所得额 = 当月佣金总额 - 800
  
  适用税率（劳务报酬）：
    不超过 20,000 元：20%
    20,000 ~ 50,000 元：30%
    超过 50,000 元：40%
  
  实际到账 = 提现金额 - 代扣个税

示例：
  当月佣金 3,000 元，申请提现 3,000 元
  应纳税所得额 = 3,000 - 800 = 2,200 元
  代扣个税 = 2,200 × 20% = 440 元
  实际到账 = 3,000 - 440 = 2,560 元
```

## 五、绑定有效期与自动解绑流程

### 6.1 绑定有效期规则

```
A（被推荐人）绑定到 B（推广人）名下后：

绑定建立时间 ──────────────────────────────────────▶
    │                                              │
    │    6 个月内无上户（默认）                      │
    │    ┌─────────────────────────────┐           │
    └───▶│ 系统每日扫描绑定关系         │           │
         │ 检查 A 是否有上户记录       │           │
         └─────────────────────────────┘           │
                    │                              │
         无上户 ────┼──── 有上户                   │
                    │                              │
                    ▼                              ▼
              ┌──────────┐                  ┌──────────┐
              │ 到期前7天 │                  │ 绑定续期 │
              │ 通知 B    │                  │ 重新计算 │
              │ "张阿姨即将│                  │ 6个月有效期│
              │  到期解绑" │                  │          │
              └────┬─────┘                  └──────────┘
                   │
                   ▼
              ┌──────────┐
              │ 自动解绑  │
              │ A→B 关系  │
              │ 清除      │
              └────┬─────┘
                   │
                   ▼
              ┌──────────┐
              │ A 变为    │
              │ 自由人    │
              │ 可被重新  │
              │ 绑定      │
              └──────────┘
```

### 6.2 解绑触发条件

| 条件 | 说明 | 通知对象 |
|------|------|----------|
| **到期自动解绑** | 绑定后 X 个月无上户，系统自动解绑 | 通知 B（推广人） |
| **人工解绑** | 运营人员在后台手动解除 A→B 绑定 | 通知 A 和 B |
| **被推荐人注销** | A 主动注销平台账号 | 通知 B |

### 6.3 解绑后处理

- A 的个人信息保留，但推广归属清空
- A 可再次被其他推广人绑定（需重新完成绑定流程）
- B 的历史佣金记录保留，不可追溯修改
- A 的历史上户记录保留，但不再关联到 B

## 七、二级分销佣金分配流程

### 8.1 分销层级关系

```
一级分销商（渠道/员工/培训机构）
  └── 二级分销商（月嫂/阿姨）
        └── 被推荐人（新月嫂）
```

### 8.2 佣金分配时机

```
被推荐人已下户 → 计算总佣金 → 按配置比例拆分 → 分别计入一级/二级余额

示例：
  新月嫂 C 完成订单，合同金额 15,000 元
    │
    ▼
  总佣金 = 15,000 × 0.5% = 75 元
    │
    ▼
  一级（员工小李）= 75 × 80% = 60 元
  二级（月嫂张阿姨）= 75 × 20% = 15 元
    │
    ▼
  分别进入小李和张阿姨的待结算池
```

### 8.3 一级分销商专属流程

| 功能 | 说明 |
|------|------|
| 发展二级 | 一级可邀请/注册二级分销商 |
| 团队看板 | 查看自己发展的所有二级分销商列表及业绩汇总 |
| 佣金分成 | 二级产生的每笔佣金，一级按配置比例自动分成 |
| 不参与绑定 | 一级不直接与月嫂建立绑定关系，只与二级建立管理关系 |

### 8.4 二级分销的限制

- 最多 **两级**（渠道→月嫂→新月嫂），禁止三级及以上
- 一级和二级均需完成实名认证
- 二级被推荐人的奖励次数上限，只针对二级推广人计算，不影响一级分成

## 九、转介绍专属流程（在岗阿姨简化版）

### 9.1 流程特点
在岗阿姨（被推荐人同时也是推广人）与普通推广人不同，她们：
- 不熟悉复杂操作，需要极简流程
- 需要即时反馈，增强动力

### 9.2 简化注册流程

```
普通推广人注册：                  在岗阿姨转介绍注册：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
① 填写手机号                      ① 填写手机号
② 填写验证码                      ② 填写验证码
③ 勾选协议          ───────▶    ③ 勾选协议
④ 注册成功                        ④ 注册成功

> **注**：注册时无需填写姓名、身份证号、银行卡等信息。首次提现时需在钱包页面补充银行卡信息（姓名/身份证/开户行/银行卡号）。所有推广人统一使用银行卡提现，暂不支持微信红包。
```

### 9.3 即时反馈机制

| 触发事件 | 反馈方式 | 内容 |
|----------|----------|------|
| 被推荐人报名成功 | 系统通知（后续接入微信订阅消息） | "恭喜！您推荐的 XXX 已报名" |
| 被推荐人签约成功 | 系统通知（后续接入微信订阅消息） | "太棒了！您推荐的 XXX 已签约，预计佣金 ¥XXX" |
| 被推荐人上户成功 | 系统通知（后续接入微信订阅消息） | "🎉 XXX 已上户！" |
| 已下户 | 系统通知（后续接入微信订阅消息） | "XXX 的服务已完成，佣金 ¥XXX 已可结算" |
| 月度结算完成 | 系统通知（后续接入微信订阅消息） | "本月结算已完成，共到账 ¥XXXX" |

> **注**：当前原型阶段使用页面内提示（alert/Toast）模拟通知，正式小程序上线后接入微信订阅消息。
